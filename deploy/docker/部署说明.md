# AI PM 内网 Podman 离线部署说明

适用目标机器：`10.92.20.201`。浏览器入口：

```text
http://10.92.20.201:9528
```

本部署包包含两个镜像：

```text
localhost/aipm-api:latest
localhost/aipm-web:latest
```

`aipm-web` 对外暴露 `WEB_PORT`，并通过 Nginx 把同源 `/api/*` 代理到内部 `aipm-api:8000`。后端大模型连接只通过 `.env.docker` 注入，不写入镜像。

## 1. 部署目录

建议放到：

```bash
/data/sdv1/qdmdata/pm-docker
```

目录结构：

```text
pm-docker/
├── docker-compose.yml
├── .env.docker.example
├── .env.docker
├── images/
│   └── aipm_images.tar
├── data/
│   ├── PRD_template/
│   ├── ic_substrate/
│   ├── prd_docs/
│   └── design_docs/
└── recordings/
```

`postgres_data` volume、`data/prd_docs/`、`data/design_docs/` 和 `recordings/`
是运行数据。更新系统时先备份，不要直接删除。

## 2. 准备环境变量

进入部署目录：

```bash
cd /data/sdv1/qdmdata/pm-docker
cp .env.docker.example .env.docker
vi .env.docker
```

推荐配置如下。注意 URL 必须是纯文本，不要粘贴成 Markdown 链接格式。

```env
WEB_PORT=9528
DOCKER_PLATFORM=linux/amd64

VITE_API_BASE_URL=
VITE_GO_CODING_URL=http://10.92.20.201:9529

HOST=0.0.0.0
PORT=8000
DEBUG=False
POSTGRES_USER=aipm
POSTGRES_PASSWORD=<填写强密码>
POSTGRES_DB=aipm
DATABASE_URL=postgresql://aipm:<填写 URL 编码后的强密码>@postgres:5432/aipm
DOCUMENT_STORAGE_PATH=/app/data
CORS_ORIGINS=http://10.92.20.201:9528,http://localhost:9528,http://localhost:3000,http://localhost:5173,http://localhost:9530

LLM_PROVIDER=openai_compatible
LLM_BASE_URL=http://10.92.20.200:4000/v1
LLM_API_KEY=<填写内网网关 key>
LLM_MODEL=ATS_EXTREME
LLM_TIMEOUT_SECONDS=500
LLM_MAX_RETRIES=2
LLM_DEBUG_STREAM=false
LLM_GCP_PROJECT_ID=
LLM_GCP_LOCATION=global
LLM_GCP_CREDENTIALS_PATH=
LLM_PROXY_URL=

LOG_LEVEL=INFO
LOG_FILE=app.log

ASR_APP_ID=
ASR_ACCESS_TOKEN=
ASR_SECRET_KEY=
ASR_BASE_URL=
```

后端会请求：

```text
${LLM_BASE_URL}/chat/completions
```

## 3. 加载离线镜像

```bash
podman load -i images/aipm_images.tar
podman images | grep 'localhost/aipm'
```

应该看到：

```text
localhost/aipm-api   latest
localhost/aipm-web   latest
```

如果镜像名称不一致，请先不要启动，检查 `docker-compose.yml` 里的 `image:` 是否和 `podman images` 输出一致。

## 4. 启动服务

```bash
mkdir -p data/prd_docs data/design_docs recordings
podman-compose --env-file .env.docker up -d
```

如果服务器没有 `podman-compose`，但有 `podman compose`：

```bash
podman compose --env-file .env.docker up -d
```

查看容器：

```bash
podman ps | grep aipm
```

访问：

```text
http://10.92.20.201:9528
```

## 5. 验证

前端首页：

```bash
curl -I http://127.0.0.1:9528/
```

API 基础检查：

```bash
curl http://127.0.0.1:9528/api/templates
curl http://127.0.0.1:9528/api/sessions
```

正常情况下 `/api/templates` 会返回模板列表，`/api/sessions` 会返回会话列表。

大模型检查：在页面里新建对话，发送一句需求。如果没有回复，先看后端日志：

```bash
podman logs -f aipm_api
```

Vibe Coding 跳转检查：生成 PRD 和设计文档后点击 `Vibe Coding`，浏览器应跳到 `http://10.92.20.201:9529`，并带上非空 `pm_api_base_url` 参数。

## 6. 常用运维命令

查看容器：

```bash
podman ps | grep aipm
```

查看日志：

```bash
podman logs -f aipm_api
podman logs -f aipm_web
```

重启：

```bash
podman restart aipm_api aipm_web
```

停止并删除容器：

```bash
podman rm -f aipm_web aipm_api
```

## 7. 更新部署

先备份运行数据：

```bash
mkdir -p backups
tar -czf backups/aipm_data_$(date +%Y%m%d_%H%M%S).tar.gz data recordings
```

停止旧容器：

```bash
podman rm -f aipm_web aipm_api
```

替换新的部署包文件后，重新加载镜像：

```bash
podman rmi -f localhost/aipm-web:latest localhost/aipm-api:latest
podman load -i images/aipm_images.tar
podman-compose --env-file .env.docker up -d
```

如果使用 `podman compose`：

```bash
podman compose --env-file .env.docker up -d
```

更新后重新执行第 5 节验证。

## 8. 常见问题

如果提示容器名冲突：

```bash
podman rm -f aipm_web aipm_api
podman-compose --env-file .env.docker up -d
```

如果 Podman 提示选择镜像源，例如 `docker.io/library/...`，不要选择。这通常表示本地镜像名和 `docker-compose.yml` 不一致。检查：

```bash
podman images | grep aipm
grep 'image:' docker-compose.yml
```

如果页面能打开但 AI 不回复，重点检查：

```env
LLM_BASE_URL
LLM_API_KEY
LLM_MODEL
```

如果日志出现专家知识包缺失，确认文件存在：

```bash
test -f data/ic_substrate/domain_pack.json && echo OK
```

如果浏览器跨域报错，确认 `CORS_ORIGINS` 至少包含：

```text
http://10.92.20.201:9528
```

## 9. 重新打包镜像

在开发机仓库根目录准备一个构建用 env 文件，例如 `/tmp/aipm-podman.env`。前端跳转地址是在镜像构建时写入的，所以必须包含：

```env
VITE_API_BASE_URL=
VITE_GO_CODING_URL=http://10.92.20.201:9529
DOCKER_PLATFORM=linux/amd64
```

执行：

```bash
ENV_FILE=/tmp/aipm-podman.env ./scripts/build-offline-docker-package.sh
```

生成物位于：

```text
release/aipm-docker-offline-YYYYMMDD_HHMMSS.tar.gz
```

把该压缩包上传到内网服务器，解压后按本文档第 2 节开始部署。
