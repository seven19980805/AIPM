# AI PM 内网 Podman 离线部署说明

这台服务器只有 Podman，没有 Docker。部署时不要执行 `*.sh` 脚本，按下面命令逐条执行即可。

## 1. 目录结构

建议部署目录：

```bash
/data/sdv1/qdmdata/pm-docker
```

目录应包含：

```text
pm-docker/
├── docker-compose.yml
├── .env.docker.example
├── .env.docker
├── images/
│   └── aipm_images.tar
├── data/
│   ├── PRD_template/
│   ├── ic_substrate/
│   ├── prd_docs/
│   └── design_docs/
└── recordings/
```

`data/prd_docs/`、`data/design_docs/` 和 `recordings/` 是持久化目录，不要删除。`data/PRD_template/` 和 `data/ic_substrate/` 是系统随包提供的模板和专家知识包，更新部署时要同步替换。

## 2. 准备环境变量

进入部署目录：

```bash
cd /data/sdv1/qdmdata/pm-docker
```

如果还没有 `.env.docker`：

```bash
cp .env.docker.example .env.docker
vi .env.docker
```

当前建议值：

```env
WEB_PORT=9528
DOCKER_PLATFORM=linux/amd64
VITE_API_BASE_URL=
VITE_GO_CODING_URL=http://10.92.20.201:9529

HOST=0.0.0.0
PORT=8000
SQLITE_DB_PATH=/app/data/rqmd.sqlite3
CORS_ORIGINS=http://10.92.20.201:9528,http://localhost:9528

LLM_PROVIDER=openai_compatible
LLM_BASE_URL=http://10.92.20.200:4000/v1
LLM_API_KEY=你的key
LLM_MODEL=ATS_MAX
```

注意：后端会请求 `${LLM_BASE_URL}/chat/completions`。

## 3. 加载离线镜像

执行：

```bash
podman load -i images/aipm_images.tar
```

确认镜像名必须是：

```bash
podman images | grep 'localhost/aipm'
```

应该看到：

```text
localhost/aipm-api   latest
localhost/aipm-web   latest
```

如果不是这两个名字，`docker-compose.yml` 里的 `image` 必须和 `podman images` 看到的名字一致。

## 4. 首次启动

先创建目录：

```bash
mkdir -p data/prd_docs data/design_docs recordings
```

启动：

```bash
podman-compose --env-file .env.docker up -d
```

如果服务器没有 `podman-compose` 命令，但 `podman compose` 可用：

```bash
podman compose --env-file .env.docker up -d
```

访问：

```text
http://10.92.20.201:9528
```

健康检查：

```bash
curl http://127.0.0.1:9528/api/sessions
```

正常会返回类似：

```json
{"sessions":[]}
```

Vibe Coding 跳转检查：

```text
http://10.92.20.201:9528
```

在 AI PM 页面生成 PRD 和设计文档后点击 `Vibe Coding`。跳转到 `9529` 时，浏览器地址栏应包含非空参数：

```text
pm_api_base_url=http%3A%2F%2F10.92.20.201%3A9528
```

如果看到 `pm_api_base_url=` 为空，说明前端仍是旧版本，需要重新加载本次新的 `aipm-web` 镜像并重启容器。

## 5. 如果启动中断或容器名冲突

如果看到：

```text
container name "aipm_api" is already in use
container name "aipm_web" is already in use
```

说明上一次启动中断后留下了半成品容器。执行：

```bash
podman rm -f aipm_web aipm_api
```

然后重新启动：

```bash
podman-compose --env-file .env.docker up -d
```

## 6. 常用命令

查看容器：

```bash
podman ps | grep aipm
```

查看后端日志：

```bash
podman logs -f aipm_api
```

查看前端日志：

```bash
podman logs -f aipm_web
```

停止并删除本系统容器：

```bash
podman rm -f aipm_web aipm_api
```

## 7. 更新部署

先备份数据：

```bash
mkdir -p backups
tar -czf backups/aipm_data_$(date +%Y%m%d_%H%M%S).tar.gz data recordings
```

停止旧容器：

```bash
podman rm -f aipm_web aipm_api
```

替换新的部署包后，先确认专家知识包存在：

```bash
test -f data/ic_substrate/domain_pack.json && echo OK
```

重新加载镜像并启动：

```bash
podman rmi -f localhost/aipm-web:latest localhost/aipm-api:latest
podman load -i images/aipm_images.tar
podman-compose --env-file .env.docker up -d
```

## 8. 排查

如果 Podman 提示选择镜像源，例如：

```text
Please select an image
registry.access.redhat.com/...
docker.io/library/...
```

不要选择。这表示 compose 文件里的镜像名和本地镜像名不一致。请确认：

```bash
podman images | grep aipm
cat docker-compose.yml | grep image:
```

两边都应该是：

```text
localhost/aipm-api:latest
localhost/aipm-web:latest
```

如果 AI 不回复，查看后端日志：

```bash
podman logs -f aipm_api
```

重点检查 `.env.docker`：

```env
LLM_BASE_URL
LLM_MODEL
LLM_API_KEY
```

如果日志出现：

```text
FileNotFoundError: /app/data/ic_substrate/domain_pack.json
```

说明部署包或镜像是旧的，缺少 IC Substrate 领域知识包。请使用包含 `data/ic_substrate/domain_pack.json` 的新离线包，重新加载镜像并重启：

```bash
podman rmi -f localhost/aipm-web:latest localhost/aipm-api:latest
podman load -i images/aipm_images.tar
podman rm -f aipm_web aipm_api
podman-compose --env-file .env.docker up -d
```

如果 Vibe Coding 页面一直停在 `Loading...`：

1. 检查跳转 URL 里 `handoff_token` 是否存在。
2. 检查跳转 URL 里 `pm_api_base_url` 是否为空。
3. 如果 `pm_api_base_url` 为空，重新部署最新前端镜像：

```bash
podman rm -f aipm_web
podman-compose --env-file .env.docker up -d
```

4. 如果 `pm_api_base_url` 不为空但仍 Loading，检查 Vibe Coding 服务是否能访问 AI PM：

```bash
curl http://10.92.20.201:9528/api/sessions
```
