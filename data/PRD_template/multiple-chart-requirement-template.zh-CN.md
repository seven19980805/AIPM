## 2. 背景与目标

### 2.1 背景

[描述当前多图表页面需求、涉及的数据源、要回答的业务问题，以及为什么需要一个统一协调的看板视图。]

说明：该页面应为来自一个或多个 QDM 数据源的多个图表提供统一视图。用户需要能够筛选、对比、下钻和导出图表级洞察，同时实现应保持轻量、响应式，并符合 AITC 企业 UI 风格。

### 2.2 目标

- 提供一个响应式看板页面，以一致的筛选和视觉风格展示多个相关图表。
- 支持用户按时间、分类、状态、组织或其他已批准维度对比指标。
- 在业务负责人定义图表关系时，支持下钻和交叉筛选。
- 标准化图表配置字段，使未来新增图表尽量减少重复开发。
- 定义布局、性能、可访问性、数据准确性和浏览器兼容性的验收标准。

### 5.3 字段逻辑与数据规则

- 开发前必须定义每个数据源之间的关联键和关系。
- 明确每个图表使用原始记录、聚合记录还是预计算指标。
- 在图表清单中记录所有公式、筛选、排除项、空值处理和舍入规则。
- 两个图表使用同一指标时，应采用相同计算逻辑，除非明确记录例外。
- 所有可见标签、单位和图例必须与已批准业务术语一致。

## 6. 页面 / 功能布局

页面应根据业务优先级、数据密度和屏幕尺寸选择一种布局模式。分析类页面建议默认使用 Primary-Detail / Hero 布局，监控类看板可使用 Uniform Grid 作为备选。

| 布局选项 | 说明 | 适用场景 | 建议 |
| --- | --- | --- | --- |
| Uniform Grid / 统一网格 | 所有图表容器尺寸一致，按统一网格对齐。 | 监控看板和同级 KPI 对比。 | 所有图表重要性相近时使用。 |
| Primary-Detail / Hero | 一个主图表占据主要区域，辅助图表位于旁边或下方。 | 有一个核心趋势或业务问题的详细分析页。 | 默认推荐，除非业务负责人确认其他布局。 |
| Nested / Drill-down | 选择一个图表会更新或筛选另一个图表。 | 探索式分析、群组/分类下钻。 | 仅在图表关系明确时使用。 |
| Tabbed / 标签页 | 多个相关图表共用一个容器，通过标签切换。 | 日 / 周 / 月等同质数据视图。 | 节省空间，但避免隐藏关键图表。 |
| Masonry / Waterfall | 卡片宽度一致，高度随内容变化。 | 混合媒体报告或移动优先信息流。 | 不建议用于核心运营看板，可能降低可比性。 |

## 9. 查询条件与用户交互

### 9.1 筛选器

| 筛选项 | 控件类型 | 默认值 | 作用范围 | 备注 |
| --- | --- | --- | --- | --- |
| 日期范围 / 周期 | 日期选择器或分段周期控件 | 最新可用周期 | 除明确排除外适用于所有图表 | 趋势和对比视图必需。 |
| 组织 / 实体 | 下拉 / 可搜索选择器 | 用户默认范围 | 所有适用图表 | 遵循用户权限范围。 |
| 分类 / 状态 | 下拉 / 多选 | 全部 | 分类、状态、构成图 | 使用已批准业务标签。 |
| 数据源 | 下拉 / 隐藏参数 | 主数据源 | 数据源特定图表 | 仅在用户需要切换来源时展示。 |
| 重置 | 按钮 | N/A | 整页 | 恢复已批准默认筛选状态。 |

### 9.2 交互规则

- 筛选变化应在技术可行时更新所有受影响图表，不要求整页刷新。
- 被选中的图表区域应有清晰激活状态，并让用户看到当前生效筛选。
- Tooltip 在桌面端应可读，在触屏设备上需替换为适合点击的详情行为。
- 如果图例可交互，必须支持键盘访问。
- 导出操作必须遵循数据权限规则，并尽可能包含当前筛选上下文。

## 10. UI 与视觉设计要求

实现应遵循 AITC 企业 UI 风格：干净、运营型、可信、信息密度适中且可读，以中性色表面和蓝色主操作为基础。

| UI 区域 | 要求 |
| --- | --- |
| 色彩系统 | 使用背景 #f6f8fb / #f3f5f7、面板 #ffffff、主蓝 #2563eb、悬浮 #1d4ed8、边框 #d9e1e7、文本 #111315 / #17202a。不要将绿色或紫色作为主品牌色。 |
| 字体 | 优先 Arial Nova，其次 Plus Jakarta Sans、Arial 和中文回退字体。避免过重字重和负字距。 |
| 间距和圆角 | 使用 8px 间距节奏，通用圆角 8px，密集控件圆角 6px。 |
| 卡片 / 面板 | 使用白色图表面板，标题清晰、内边距一致，仅在需要时使用轻量阴影。 |
| 响应式布局 | 桌面优先对比，平板保持图表可读，移动端纵向堆叠图表，只有真实表格可横向滚动。 |
| 状态 | 为筛选器和图表定义加载、空、错、禁用、激活、悬浮、聚焦和选中状态。 |

## 11. 技术规格

| 类别 | 要求 |
| --- | --- |
| 前端技术栈 | HTML + Bootstrap + JavaScript/jQuery。代码应清晰、结构化、必要处注释，并便于二次开发。 |
| 图表库 | 使用已批准的轻量图表库或项目既有标准；除非架构评审批准，否则避免复杂插件。 |
| 响应式 | 支持桌面、平板和移动断点。使用原生响应式网格，避免导致溢出的固定宽度。 |
| 性能 | 初始页面应快速渲染框架；图表尽量异步加载。正常数据量下目标图表刷新 3 秒内完成，具体取决于 API 性能。 |
| 浏览器支持 | 支持企业当前批准的 Chrome 和 Edge 版本，其他浏览器要求待确认。 |
| 可维护性 | 分离数据映射、图表配置和渲染逻辑，使未来新增图表尽量可配置。 |
| 安全 | 遵循基于角色的数据访问；防止未授权导出受限数据，避免在客户端暴露敏感原始字段。 |

## 12. 非功能需求

| 需求类型 | 目标 / 规则 | 验证方法 |
| --- | --- | --- |
| 数据准确性 | 同一筛选条件下展示值必须与已批准来源查询结果一致。 | QA 对比来源查询或已验证报表。 |
| 性能 | 正常筛选或图表刷新应在约定 SLA 内完成，标准数据量下目标 3 秒。 | 浏览器计时和 API 日志检查。 |
| 可访问性 | 控件可键盘访问、聚焦状态可见、对比度充足，状态表达不能只依赖颜色。 | 手工键盘测试和对比度评审。 |
| 可靠性 | 单个图表失败不应破坏整页，应展示图表级错误态。 | 模拟 API 失败测试。 |
| 兼容性 | 页面在批准的桌面、平板、移动宽度下保持可读。 | 响应式浏览器验证。 |
| 可审计性 | 最后刷新时间和当前筛选上下文应尽量在页面或导出元数据中可见。 | 功能测试和导出检查。 |

## 13. 验收标准

- 业务负责人确认图表清单、指标定义、筛选清单、默认视图和布局模式。
- 数据负责人确认来源表/视图/API、字段映射、刷新频率、关联逻辑和计算规则。
- 所有图表在默认筛选和至少三组代表性筛选组合下正确渲染。
- 加载、空态、错误、激活、悬浮、聚焦和禁用状态已实现且视觉一致。
- 页面在桌面、平板和移动宽度下响应式正常，无文本截断、控件重叠或不可读标签。
- 导出行为遵循已批准数据权限规则，并在适用时包含当前筛选上下文。
- QA 根据来源查询或已批准参考报表验证数据准确性。
- 最终页面遵循批准色彩系统，不引入未批准主色或重装饰风格。
